Marketplace Payment Loop

Provides persistent service publishing and discovery; the payment lifecycle remains under verification.

The live service now runs on Supabase Edge with persistent PostgreSQL, RLS-denied direct access, indexed marketplace tables and server-managed sessions. Registration, authentication, publishing and search have passed a deployed end-to-end check. The hosted page script, database health probes and session error handling are regression-tested. Checkout settlement is implemented as one restricted PostgreSQL transaction and has passed CI. On 2026-09-03, the migration was applied to hosted PostgreSQL and a disposable transaction verified initial settlement, duplicate suppression and rollback without retaining test records; Edge Function v4 was deployed. Registration and first-session creation are also atomic: a forced session conflict leaves no orphan user, verified against hosted PostgreSQL. Listing search now passes text to a restricted PostgreSQL function instead of PostgREST filter grammar; metacharacters and execution privileges were verified in a rollback-only hosted transaction. Current-session logout deletes the hashed server-side session before clearing browser state, and Edge Function v7 is deployed. External HTTP probing was blocked by the verification environment, so current uptime is not claimed. Payments remain disabled pending refund implementation and real Stripe tests—not just credentials.

Vesper Commerce Ops

Normalizes official order exports from seven commerce channels into one auditable ledger.

The Chinese/English console covers Amazon, Taobao/Tmall, Pinduoduo, Douyin Shop, Xiaohongshu, Shopify and WooCommerce. Deployed end-to-end checks verified registration, authenticated shop creation, transactional CSV import, and owner-scoped shop/channel history. The canonical ledger can be filtered by shop through the authenticated API; disposable two-shop checks returned two orders globally and one for the selected shop, then deleted all test data. The applied tables, indexes, RLS policies and atomic import function are tracked as repository migrations. Direct channel APIs remain disabled until real merchant authorization.
